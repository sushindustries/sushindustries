Every task in this repository, as documents. The backlog lives here rather
than in a tracker for the same reason everything else does: the studio already
searches documents, collections already group them, the MCP server already
reads them, and the graph already serves them. A tracker would be a second
place work lives and a fifth surface to keep in step.

Each one says why before it says what. The reason is the expensive part to
reconstruct three weeks later, and it is what decides whether a task still
matters by then - a feature description ages into a plan nobody remembers
agreeing to.
